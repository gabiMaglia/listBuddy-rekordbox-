Buddy: listas propias, armadas arrastrando desde Rekordbox y Traktor

Tres variantes del mismo contenido para elegir el layout. En las tres, cada panel es un «browser»: lista de listas, click abre las pistas, flecha para volver. Los mockups son clickeables (abrir una lista, volver, menú contextual en «Mis listas»). Los datos son de ejemplo.

A favor

  • Es lo que pediste: 2 fuentes arriba, lista propia abajo con el doble de espacio.
  • El arrastre es vertical y corto (de arriba hacia abajo), fácil de apuntar.
  • Las dos fuentes se ven a la vez: sirve para armar una lista mezclando RB y Traktor.

En contra

  • Los paneles de arriba quedan bajos (200 px): con 800 playlists se navega con mucho scroll.
  • Pista de 3 columnas (Nº, nombre, key·bpm) apretada en media ventana.
  • Si solo tenés una fuente cargada, media fila superior queda vacía.

Elegida por el PO (2026-10-19), con dos agregados

  • Cada fila de la columna izquierda es una fuente independiente con su propio selector Rekordbox | Traktor: podés tener Techno 2025 de Rekordbox arriba y Sets de Traktor abajo, y arrastrar desde las dos.
  • «+ Agregar fuente» suma una fila; tope 9. Cada fila se cierra con ×. Las filas reparten la altura en partes iguales con un divisor horizontal.
  • El divisor vertical entre fuentes y «Mis listas» se arrastra (probalo acá): el ancho se recuerda en settings.ini.

Qué implica

  • En Qt es un QSplitter horizontal (fuentes | Mis listas) con un QSplitter vertical adentro para las filas: ambos nativos, con el handle teñido por token.
  • Cada fila es la misma clase SourceBrowser; 9 filas son 9 vistas sobre el mismo modelo de librería (no se vuelve a leer el XML).
  • Con muchas filas cada una queda baja: a partir de la 4ª la lista interna scrollea.

Dónde y cómo se guarda

Un archivo buddy_lists.json en la carpeta de datos (la misma de settings.ini y rekordbox_fixes.json). Nunca se toca el XML ni el NML del usuario. La pista se referencia por su ruta de archivo, que es lo único que Rekordbox y Traktor tienen en común; además se guarda de qué fuente y lista vino para poder mostrarlo y para recuperar cues y beatgrid al exportar.

{
  "version": 1,
  "lists": [
    {
      "id": "b7f3…",            // uuid4, estable al renombrar
      "name": "Warm-up viernes",
      "folder": null,           // 1 nivel de carpetas (si se aprueba)
      "created": "2026-10-19T14:02:00",
      "modified": "2026-10-19T15:10:31",
      "tracks": [
        {
          "path": "/Volumes/MUSIC/House/Innerbloom.mp3",
          "title": "Innerbloom", "artist": "Rufus Du Sol",
          "bpm": 122.0, "key": "8A",
          "origin": {"source": "rekordbox", "playlist": "Techno 2025",
                     "track_id": "1842"}     // o "traktor" + KEY del NML
        }
      ]
    }
  ]
}
Por qué JSON y no SQLite

Pocas listas, pocos miles de pistas como mucho, lectura al abrir y escritura atómica al cambiar (mismo patrón os.replace de las fixes). Sin dependencia nueva, diffeable, y fácil de respaldar o compartir.

Escritura

Cada cambio (crear, mover, quitar) escribe el archivo entero a .tmp y lo reemplaza. Un backup rotativo diario en listBuddy_backups/ como ya hace el relocate de Traktor.

Mezclar fuentes en una lista

Una pista existe en el disco una sola vez. Si la misma ruta aparece en Rekordbox y en Traktor, es la misma pista: la clave de duplicado es la ruta normalizada (ya hay una clave canónica desde D-11).

Pistas rotas

Al abrir Buddy se chequea existencia en segundo plano (PreviewWorker ya lo hace para la vista previa). Una pista rota se muestra en rojo y la exportación la salta con aviso, igual que hoy.

Lo que necesito que decidas

  1. Layout: A (2 arriba + doble abajo, como pediste), B (3 columnas) o C (fuente con el selector actual + Mis listas).
  2. Carpetas de listas propias: plano en 1.1, o un nivel de carpetas desde el arranque (cambia el JSON y el árbol).
  3. Export a Traktor: archivo .nml suelto para arrastrar (sin tocar la colección) o escribir en collection.nml con backup como el relocate. Recomiendo empezar por el suelto.
  4. Deshacer: sin deshacer en 1.1 (solo confirmación al eliminar lista), o pila de undo para quitar/mover/eliminar. Recomiendo confirmación sola en 1.1 y undo en 1.2.
  5. Reproducción: el reproductor del footer sirve para las tres cajas (click en pista reproduce, como hoy en la vista previa).
  6. Navegación: «Listas | Buddy» como segmented control en el header (mockups) o dos pestañas. Configuración sigue en ⚙.
