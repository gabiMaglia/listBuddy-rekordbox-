Fila T-108 de `engram/03_backlog.md`: **Windows build con integridad**: `build_windows.ps1` crea `.venv-build` limpio (no
reutiliza `.venv`), exige Python >= 3.14.8, instala con `--require-hashes`, corre un `check_bundle.ps1` (sin

Fuera de alcance: código de la app (T-106 trabaja en `ui.py`), release automático de Windows, attestation (SEC-20 punto 2,
queda como deuda), firma Authenticode.

2. **Lock de build Windows.** `requirements-build-windows.in` = `pyinstaller==6.22.3`, `pip==26.1.2`, `pefile`,
   `pywin32-ctypes` (PyInstaller 6.22.3 los exige con `sys_platform == 'win32'`: verificado en el METADATA del wheel
   `win_amd64`). `pip-compile` resuelve para el host y evalúa los marcadores ahí (docs pip-tools), por eso pefile y
   pywin32-ctypes van explícitos; los hashes cubren todos los wheels del release (pip-tools >= 1.10). El lock trae además
   `macholib` (marcador darwin, puro Python, inocuo en Windows). Se verifica con `pip download --platform win_amd64
   --only-binary=:all: --require-hashes -r requirements-build-windows.txt`. CLAUDE.md (sección Windows) documenta el
   comando de regeneración. Verif.: test que exige pefile/pywin32-ctypes/pyinstaller 6.22.3 con hash, sin paquetes sin
   hash, y el comando en CLAUDE.md.
3. **`check_bundle.ps1` + patrones compartidos.** `scripts/bundle_forbidden.txt` (un glob por línea, sobre el NOMBRE,
   sin distinguir mayúsculas) lo leen `check_bundle.sh` y `check_bundle.ps1`: pyrekordbox, sqlcipher, sqlalchemy,
   `.rbe_settings.ini`, QtPdf/Qt6Pdf, QtQuick, QtQml, QtVirtualKeyboard, qpdf, QtWebEngine, `PIL`, `Pillow*`, `PyQt6*`.
   Ejecución: `check_bundle.ps1 [-Path dist\listBuddy]`, exit 2 si no existe, 1 si hay prohibidos. Verif.: el `.sh` con
   carpetas falsas parametrizadas sobre CADA patrón del archivo (la lista se enumera, no se eligen ejemplos); test
   estático del `.ps1` (lee el mismo archivo, `-like`, `-Force`, exit 1/2) y de que el `.sh` ya no lleva la lista a mano.
1. **`build_windows.ps1` reescrito.** Pasos, cada uno con `$LASTEXITCODE` chequeado: (a) Python >= 3.14.8 (parámetro
   `-Python`, default `python`) con mensaje de cómo instalarlo; sin override; (b) gate D-14 (los mismos 4 archivos que
   `tests/test_release_gate.py`; un test exige igualdad); (c) borra y recrea `.venv-build` (nunca toca `.venv`);
   (d) `python -m pip install --require-hashes` de `requirements.txt` y luego del lock de Windows; (e) borra
   `dist\listBuddy` y artefactos del mismo nombre; (f) `python -m PyInstaller rb_exporter.spec --noconfirm --clean`;
   (g) `check_bundle.ps1`; (h) zip con `ZipFile.CreateFromDirectory` (entradas con `/`; se reabre y se verifica que no
   haya `\` ni falte `listBuddy/listBuddy.exe`; se evita `Compress-Archive` por sus peculiaridades en PS 5.1) →
   `dist\listBuddy-<v>-win64.zip` (`<v>` sale de `_APP_VERSION` en `ui.py`, como en mac); (i) `Get-FileHash` SHA-256 ->
   `<hash> *<nombre>` (LF, sin BOM), formato que `shasum -a 256 -c` acepta (probado en macOS). Verif.: test estático que
   parsea cada línea de comando; el orden de pasos; el formato del `.sha256` replicado en Python y verificado con
   `shasum -c`.
4. **Job Windows + marcador.** `pytest.ini` declara `qt` y `posix`. `tests/conftest.py` los asigna por convención
   (sin tocar 60 archivos): un test es `qt` si su función, un helper de módulo que ella llama o un fixture que usa contiene
   `run_isolated`/`BOOT`/`PySide6`; es `posix` si usa `bash`, `shasum`, `plutil`, `chmod`/`st_mode`/permisos, symlinks o
   `getuid`. `run_isolated` aborta con `LISTBUDDY_NO_QT=1` (el job Windows lo exporta: un test mal clasificado falla fuerte

   os.replace quedan en el subconjunto; footer/ventanas quedan fuera), subconjunto verde en macOS con `LISTBUDDY_NO_QT=1`,
   test estático del job (parseo de `runs-on`, `python-version`, `--require-hashes`, `-m`), actionlint.
