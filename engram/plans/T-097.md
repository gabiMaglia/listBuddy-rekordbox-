# T-097 — Builds arm64 + Intel en GitHub Actions (APP-06)

Aprobado por el PO: 2026-10-15 (corte T-086, `engram/audit/T-086_apple.md` APP-06 §«universal2 no viable»).

## Qué
Dos builds thin de macOS (arm64 + x86_64) desde GitHub Actions, firmados con Developer ID y
notarizados cuando hay secrets; ad-hoc (sin fallar) cuando no los hay. Suite de tests en CI.
universal2 queda descartado (numpy cp314 no publica wheel universal2; APP-06).

## Fuentes verificadas (2026-10-15)
- Runners macOS hoy: `macos-15` (arm64), `macos-15-intel` (x64), `macos-26` (arm64, = `macos-latest`),
  `macos-26-intel`; `macos-14*` deprecado — [actions/runner-images README](https://github.com/actions/runner-images/blob/main/README.md).
- Intel: `macos-15-intel` es el último runner x86_64; GitHub deja de soportar Intel «after the macOS 15
  runner image is retired in Fall 2027» — [changelog 2025-09-19](https://github.blog/changelog/2025-09-19-github-actions-macos-13-runner-image-is-closing-down/).
- `macos-26` GA desde 2026 (`macos-latest` → macos-26 en junio 2026) — [changelog 2025-09-11](https://github.blog/changelog/2025-09-11-actions-macos-26-image-now-in-public-preview/).
  Se usa `macos-15` para arm64 (no `macos-latest`): mismo major en ambas patas y runner estable.
- Python 3.14.8 disponible en setup-python para darwin-arm64 y darwin-x64 —
  [actions/python-versions versions-manifest.json](https://raw.githubusercontent.com/actions/python-versions/main/versions-manifest.json).
- Versiones de acciones: `actions/checkout@v7` (v7.0.1), `actions/setup-python@v7` (v7.0.0),
  `actions/upload-artifact@v7` (v7.0.2), `actions/download-artifact@v8` (v8.0.2),
  `softprops/action-gh-release@v3` (v3.0.3; v2 sin mantenimiento) — páginas de releases de cada repo.
- Importar .p12 en keychain temporal en el runner (`security create-keychain` / `import -A -t cert -f pkcs12` /
  `set-key-partition-list -S apple-tool:,apple:` / `list-keychain -d user -s`; limpieza con `delete-keychain`) —
  [GitHub Docs: Installing an Apple certificate on macOS runners](https://docs.github.com/en/enterprise-server@3.10/actions/use-cases-and-examples/deploying/installing-an-apple-certificate-on-macos-runners-for-xcode-development)
  (la URL de github.com cambió de ruta y devolvió 404 en dos variantes; la copia ES 3.10 es la más nueva encontrada).
- `notarytool` con API key: `--key <ruta .p8> --key-id <ID> --issuer <UUID>`; `store-credentials` acepta
  los mismos flags — [TN3147](https://developer.apple.com/documentation/technotes/tn3147-migrating-to-the-latest-notarization-tool)
  y `xcrun notarytool store-credentials --help` (notarytool 1.0.0 local).
- API key: App Store Connect → Users and Access → Integrations → App Store Connect API → Team Keys;
  solo Admin la genera; el .p8 se baja **una sola vez**; las claves individuales no sirven para notaryTool —
  [Creating API Keys for App Store Connect API](https://developer.apple.com/documentation/appstoreconnectapi/creating-api-keys-for-app-store-connect-api).
  Rol: «Developer» alcanza (foro de Apple, [thread 133063](https://developer.apple.com/forums/thread/133063); no hay doc primaria).
- `secrets` no está disponible en `steps.if`, sí en `jobs.<id>.env` —
  [GitHub Docs: Contexts](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts).
  Por eso el workflow calcula `SIGNING=true/false` en `env` del job y los steps miran `env.SIGNING`.

## Archivos
- `scripts/release_mac.sh`: flag `--arch-suffix` (DMG `List Buddy-<v>-<arch>.dmg`), `PYTHON` para el venv,
  escribe `<dmg>.sha256`. Sin cambio de flujo de firma/notarización.
- `.github/workflows/release.yml`: tag `v*`, `workflow_dispatch`, `pull_request` solo si cambian archivos de
  empaquetado (smoke ad-hoc). Matriz `macos-15` / `macos-15-intel`. Keychain temporal + `store-credentials`
  si hay secrets. Release en borrador con `softprops/action-gh-release@v3` en tag.
- `.github/workflows/tests.yml`: `python -m pytest -q` en `macos-15`. Solo macOS: los tests de Qt necesitan
  fuentes, Cocoa (`test_fonts_icons`, `test_contrast`, `test_fade_lifecycle` miran SIGSEGV/stderr de un proceso
  Qt real) y no están validados en Linux.
- `tests/test_release_scripts.py`: tests de `--arch-suffix` y del `.sha256`.
- `docs/RELEASE.md` (nuevo), `README.md`, `CLAUDE.md`.
