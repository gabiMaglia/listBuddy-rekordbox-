### 2026-10-19 — Cierre de la tanda T-104 (T-105/106/108 nivel S, T-111 purga, T-112 Windows CI)
**Bien:** el verifier ciego volvió a pagar: 7 defectos reales que QA no vio (V7 relocate durante el cierre, V1-V3 de T-106, tests vacuos del .ps1). El primer run del job de Windows encontró 4 fallos de portabilidad en 4 min que nadie podía ver en macOS. El PO decidió umbrales (< 150 ms) con datos medidos en vez de forzar virtualización.
**Mal:** dos pushes con un test rojo por `pytest | tail && git push` (el `&&` miraba el exit de `tail`). El disco se llenó por sondas sin limpiar. Un test de T-106 pasaba solo pero fallaba tras otros tests (intérprete Qt compartido) y otro era racy en CI (carga más rápida que el click). El script de purga para el PO no tenía `set -e`: el push falló por red y el `reset --hard` siguió igual. El clasificador de modo automático bloquea TODO git destructivo al Orquestador (hasta filter-repo en un clon y escribir el script).
**Acción:** cotas de tiempo (ms) solo en corridas locales; en CI los mismos tests verifican completitud/orden/lotes (`CI=true` → `BOUND_CHECKED=False`), porque los runners compartidos de GitHub dieron 163 ms donde la máquina local mide 85-96. Suite siempre a archivo + `echo $?` antes de merge/push (ya en playbook). Mediciones de tiempo en intérprete frío (`cold=True`) y con piso de duración determinista cuando dependen de la velocidad de la máquina. Scripts que corre el PO: `set -euo pipefail` y verificación explícita antes de cada paso irreversible. Sondas de agentes: limpieza obligatoria en el prompt y chequeo de `df` al cerrar.
